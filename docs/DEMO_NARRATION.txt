AgentAuth is a delegated-commerce control plane for AI buyers. The core idea is simple: an AI may understand what a user wants, but understanding is not authority. AgentAuth lets one registered agent act only inside a user-approved mandate, while deterministic services control prices, inventory, spending and payment state.

This is the live local test environment. The login represents application consent, not bank identity or biometrics. Secrets stay outside the browser: Gemini and the agent private key live in the Agent API, while the Merchant API owns authorization and commerce facts.

The Recovery Lab first resets only fictional demo state. Now the user reviews the delegation. It binds one agent fingerprint to this merchant, approved categories, a per-order limit, a cumulative limit, an expiry and automatic-execution permission. Changing those limits requires a new grant, and revocation blocks future purchases.

The buyer asks: order my usual groceries under nine hundred rupees for delivery tonight. This is one Gemini commerce agent, not a chain of agents. It can read factual purchase history, search the catalog, check delivery and request a quote. Checkout remains structurally unavailable until a valid quote exists.

The model chooses products and quantities, but it never supplies identity, prices, totals, the grant, the quote identifier or the idempotency key. The merchant calculates the exact quote from current catalog, delivery and inventory data. It then revalidates every rule independently of the model.

When the order is placed, PostgreSQL performs one short atomic reservation: it enforces the cumulative allowance, locks inventory in a consistent order, consumes the quote and writes the audit event. The simulator then settles through the same grant, quote, reservation and audit pipeline. It is permanently labelled simulated and moves no real money.

The Trust Inspector shows why this is more than an AI wrapper. Every protected call carries an ES256 proof over the method, path, body digest, timestamp, nonce, grant and immutable grant digest. PostgreSQL rejects a repeated nonce even after an API restart. The inspector also separates the model's tool trace from the deterministic money facts and shows the hash-linked audit sequence.

The Recovery Lab makes failure behavior visible. Here, the same signed request is sent twice: the first succeeds and the replay is rejected. Other controls cover model timeout, duplicate or out-of-order webhooks and an ambiguous provider response.

The main failure story is a lost payment-provider Order response. AgentAuth does not blindly retry. It uses one stable receipt, observes provider state outside the database transaction, and applies the result only if the reconciliation lease is still current. Webhooks and the worker lock the same checkout, preventing stale observations from overwriting newer truth.

The optional Razorpay adapter remains honest: creating an Order is never shown as paid, and a failed attempt does not release reservations while a later capture is still possible. Without account-bound credentials, this demonstration uses the autonomous sandbox.

That separation is the product. Gemini handles language and product judgment. Cryptography proves the caller. PostgreSQL enforces shared limits and durable state. The merchant and recovery worker control money-relevant outcomes. AI can act, but only inside authority that is explicit, bounded, explainable and recoverable.
